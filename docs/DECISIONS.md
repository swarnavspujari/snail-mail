# Decisions & Assumptions

Running log of every non-default choice. Newest last.

## Stack (per spec defaults)
- **Tauri v2** (not Electron): lighter, OS-keychain access, locked-down webview, and the mobile path (iOS/Android) stays open with one codebase.
- React + TS + Vite + Zustand + **Tailwind v4** (CSS-variable tokens make dark/light a token swap; v4's Vite plugin removes the PostCSS config).
- SQLite via `rusqlite` (bundled, includes FTS5) — no external SQLite install.
- `keyring` crate → Windows Credential Manager. Chosen over `tauri-plugin-stronghold` for zero-config UX and true OS-level storage.

## Product interpretations
1. **Split counts = total conversations** in the split (not unread, not raw message count) — that's what makes a split read like a to-do list; matches Superhuman.
2. **Split matching**: first split whose rules match (settings order) claims the thread; the builtin "Other" (empty rule set) is the catch-all. Custom splits are inserted before "Other" so they win over it but not over Important/Calendar unless reordered.
3. **"Mark Done" = remove Gmail INBOX label** (archive). A reply re-adds INBOX server-side → the thread returns automatically on the next sync pass.
4. **Snooze** is local-first: archive remotely + `snoozed_until` locally; a 30s background tick returns due threads (re-adding INBOX+UNREAD remotely). A new reply wakes the thread early.
5. **Instant Reply insertion**: `Tab` previews suggestions in the thread view; `R`/`Enter` (reply / reply-all) inserts the highlighted suggestion for review. Nothing sends without an explicit `Ctrl+Enter`/Send click.
6. **`?` (Ask AI)** at P0 is thread-scoped Q&A (streams an answer grounded in the open thread + attachments). Inbox-wide Ask AI is P1 as specced.
7. **`Enter` in list opens** the conversation; in thread it's Reply-All (spec's dual meaning).
8. **Weekly streak** = `daily / 7` — consecutive zero-days roll into weeks; simplest model that matches "empty on consecutive days".
9. **Mock/demo mode**: with no account connected, both the browser build and the desktop app run on a seeded fixture inbox (same dataset in TS and Rust) so every feature is testable before credentials exist. Sent mail in demo mode appends locally.

## Technical choices
10. **DB is the UI's source of truth**; Gmail mutations are applied remotely first, then locally, so failures surface immediately and sync can't fight the UI.
11. **Sync = polling** (100 inbox + 50 recent archived threads, `historyId`-diffed) every 60s. Gmail push (Pub/Sub watch) needs a server — out of local-first scope; documented for P1 reconsideration.
12. **OAuth scope `gmail.modify`** — least privilege covering read/send/label. Not `gmail.readonly` + `gmail.send` because archive/label writes are core.
13. **AI streaming over Tauri `Channel`**; cancellation via per-request `AtomicBool` (frontend also stops listening immediately).
14. **Context budget in characters** (~4 chars/token heuristic, ≈25k tokens total). Truncation order: oldest messages' quoted trails stripped first, then oldest bodies capped, then attachment extracts capped per-file and in total. Newest message always survives intact.
15. **NIM is text-only** at P0 (vision support varies per NIM model); Claude/OpenAI get image attachments as base64 blocks. Attachment text extraction still applies to all three.
16. **.docx extraction is best-effort** (unzip → strip `document.xml` tags) per spec wording.
17. **Custom labels sync to Gmail** (name→id resolution, auto-create). Only system labels are assumed to pre-exist.
18. **Celebration images**: 4 bundled SVG landscapes ship in `public/inbox-zero/` (served from the app bundle — the spec's `assets/` folder would not be web-servable in Vite); a user folder is supported via the asset protocol, scope-limited to exactly that folder at runtime.
19. **Icons** are generated from a scripted PNG (`scripts/make-icon.mjs`) → `tauri icon`, so the repo has no unexplained binaries.
20. **Search** is FTS5 with sanitized prefix terms (alphanumerics only) — raw user input can't produce FTS syntax errors.
21. **No `.env` at runtime** — all credentials enter via the Settings UI into the keychain. `.env.example` documents what you need, nothing reads it.
22. **Repo layout deviation**: celebration assets live in `public/inbox-zero/` (not `assets/`) for bundling reasons; `tests/` holds the acceptance script pointer rather than a unit-test suite at P0 (the smoke-test checklist in SHORTCUTS.md is the verification vehicle, executed on Windows).

Building it properly (folders ↔ archive semantics, conversation threading, MIME) deserves its own release rather than a rushed appendix to this one.
26. **Trash (`#`)** uses Gmail's `threads.trash` (30-day recovery server-side); locally the thread is dropped from the cache entirely. No trash view at P0 — Gmail's web UI covers recovery; no undo yet (with Superhuman parity, `Z` undo is the natural v0.3 companion to spam/mute).
27. **Signatures are per-account** (`settings.signatures[email]`), shown as a distinct block in compose and appended between body and quote on send. Not injected into the editable body so the AI draft flow can't accidentally treat the signature as draft text.
28. **Demo mode now has two accounts** (`demo@` + `angel@fission.local`) so account switching is demonstrable with zero credentials, in both the browser mock and the desktop fixture DB.
29. **Default AI = NIM with `deepseek-ai/deepseek-v4-pro`** — supersedes the original config's Claude default because the user supplied a NIM key and asked for DeepSeek v4 (verified live: model listed + streaming works). Claude/OpenAI remain one radio-click away.
30. **`has_key` is computed from the keychain on every settings read**, not persisted — keys seeded or revoked outside the app (e.g. via `dev-secrets`) always display truthfully.
31. **`dev-secrets` bin** seeds/checks/deletes keychain entries for development; values pass via env var only. Added `default-run = "fission-mail"` so `tauri dev` still resolves.
32. **Linux (Fedora) is a declared target**: keyring grew the Secret Service backend, CI gained an ubuntu `cargo check` with WebKitGTK deps, SETUP documents Fedora/Debian packages. Full Linux smoke test gates calling it "supported".
33. **Settings merge on read**: saved settings gain new default shortcuts/providers on upgrade instead of being wiped or frozen.

## v0.3 — Undo, Undo Send/Send Later, spam/mute, starred, snippets, unsubscribe, light theme (2026-07-01)
34. **Undo (`Z`) is a frontend inverse-action stack**, not an event-sourced log: each triage action pushes its inverse (done↔not-done, trash/spam→restore, mute→unmute, snooze→inbox, star↔unstar). Local-first and honest — no fake "undo" that leaves server state changed.
35. **Trash/spam became soft-hides** (`threads.hidden` column) so undo restores instantly from the local row; server-side they use `threads.trash` / SPAM labels, and restore uses `untrash`/label-removal + INBOX re-add. Sync can't resurrect hidden threads (inbox/done queries exclude trash+spam server-side too).
36. **Undo Send = a 10-second outbox fuse.** Sends are queued in a SQLite `outbox` table and flushed by a 3s background task; `Z` inside the window reclaims the draft into compose. **Send Later** is the same mechanism with a user-picked timestamp — it survives app restarts, needs no server. Failures retry with a 5-attempt cap. Trade-off (documented): a scheduled send only leaves the machine while the app is running.
37. **Mute** = custom `Muted` label + archive; a sync pass re-archives any muted thread that resurfaces with new replies. Matches Gmail's mute semantics without server rules.
38. **Unsubscribe (`Ctrl+U`)** reads the RFC-2369 `List-Unsubscribe` header captured at sync: https targets open in the browser, mailto targets prefill a compose. No List-Unsubscribe → clear toast. One-click POST (RFC 8058) is a possible refinement.
39. **Starred view** (`G S`) lists starred threads across inbox+done for the active account. Drafts/Sent views deferred (drafts aren't synced yet; sent threads need a `q=in:sent` sync pass).
40. **Light theme** is a token-set swap on `html[data-theme]` — tuned, not inverted (deeper accents, `--on-accent` flips to white). Dark stays default per the original spec.
41. Outlook's Graph adapter moves to **v0.4** — v0.3 spent its budget on triage parity, which benefits every account type.

## v0.4 — Distribution: auto-update, release CI, signing path (2026-07-01)
42. **Updates ship via GitHub Releases + `tauri-plugin-updater`** — no server, matching local-first. `latest.json` at `releases/latest/download/` is the feed; the app checks at boot + every 4h, downloads in the background, and offers "Update ready — Restart". Updater artifacts are minisign-signed; the private key lives in `C:\Users\swarn\.fission-mail-keys\` and the `TAURI_SIGNING_PRIVATE_KEY` repo secret (losing it orphans every install — it must be backed up).
43. **Release CI = tag-triggered `tauri-action`** on `windows-latest`; the existing `build.yml` stays as the PR/push gate. Installers are **unsigned for now**: Authenticode via Azure Trusted Signing ($9.99/mo) is the documented path (docs/DISTRIBUTION.md) and needs an account only the user can create; CI wiring is written down, not faked.
44. **NSIS `installMode: passive`** for updates — the updater runs the new installer with a progress bar and no wizard clicks, closest to "it just updated itself".

## v0.5 — Real-mail robustness: HTML rendering, attachments, drafts, incremental sync (2026-07-01)
45. **HTML mail renders sanitized-on-read** (ammonia allowlist in `mail/render.rs`; raw HTML stays in the DB so the allowlist can evolve without resync). Rendering happens in a script-less `sandbox="allow-same-origin"` iframe on a white "paper" card — dependable for real newsletters that assume a light background; height tracks content via ResizeObserver; links open in the system browser. Remote images are allowed (tracking-pixel tradeoff, same call Superhuman makes); `cid:` inline images resolve to data: URIs, fetched once (≤2 MB) and cached in `attachments.data`.
46. **Attachments**: bytes are fetched lazily (open/save actions), cached ≤25 MB in SQLite; compose attaches via a native file input (base64 over IPC, so the restart-surviving outbox keeps working). `build_rfc822` grew multipart/mixed + multipart/alternative.
47. **Drafts are local-only** (`drafts` table, opaque JSON payload). Esc = save + toast, Discard = delete, autosave every 800ms, `G D` resumes. Gmail-side draft sync deferred — local-first covers the "don't lose my work" promise without a sync headache.
48. **Sync is history.list-first**: per-account `history:<email>` baseline in kv; incremental pass refetches only affected threads (any thread, not just the newest 100); 404 (expired id) falls back to the old reconcile pass, now paginated (inbox 500 / done 200 threads). Initial backfill of 500 threads takes a minute of sequential fetches — acceptable one-time cost, documented here instead of hidden.
49. **Threading UX**: older messages collapse to one-line headers (avatar + snippet), last + unread stay open, quoted trails (`On … wrote:`, `gmail_quote`, trailing blockquotes) hide behind `•••` in both text and HTML modes.

## v0.6 — First-run experience + reported bugs (2026-07-02)
50. **v0.5.0 was not released separately** — item-3 code was already on the branch before item-2's smoke pass finished, and tagging mid-branch would have shipped updater artifacts whose self-reported version (0.4.0) disagreed with the tag. v0.5+v0.6 ship together as v0.6.0; the release train resumes one-tag-per-item after this.
51. **Onboarding is a 4-step gate** (connect → AI key → theme → 10-key tour) on `settings.onboarded`; replayable from Settings → Appearance. Existing upgraders see it once — that's intended, it doubles as the "what's new" tour.
52. **Account switching is Alt+1–9** (user preference; Ctrl+N kept free for browser muscle memory). Saved settings that still carry the old default (mod+N) migrate on read; custom remaps survive.
53. **A beta Google OAuth client can be baked in at build time** (`FISSION_GMAIL_CLIENT_ID/SECRET` env → `option_env!`), so testers never open the Google console. Desktop clients can't keep secrets by design (PKCE still guards the flow; Thunderbird et al. ship theirs the same way). Keychain-pasted credentials always win. CI reads them from repo secrets; `scripts/set-oauth-secrets.ps1` pushes them from the local keychain (run once by the owner).
54. **OAuth scopes grew to `gmail.modify openid email profile calendar.readonly`** in one step so each tester consents exactly once. Accounts connected before v0.6 need a Disconnect → Connect to grant the new scopes (profile photo + calendar panel appear after reconsent).
55. **Signatures are sanitized rich HTML** (paste straight from Gmail's signature box, images inline as data: URIs, ≤500 KB per image). Plain-text signatures keep the old all-text send path; rich ones add a multipart/alternative HTML body. Sanitization happens at save AND render (pasted rich text is untrusted).
56. **Sender avatars are deterministic monograms** (hue from email); the account's own photo comes from the OpenID userinfo endpoint, cached as a data: URI, overridable in Settings. Other people's Google photos need People-API contacts scope — declined (more consent friction than the feature is worth at beta).
57. **New-mail notifications** fire from the 30s background loop for unread-in-inbox threads newer than a boot-time watermark, only while the window is unfocused; toggle in Settings → Appearance. Window size/position persists via tauri-plugin-window-state.
58. **Vite ignores `src-tauri/**`** — Rust saves no longer full-reload the webview (bit the smoke-test agent; would bite anyone running browser + Rust dev side by side).

## v0.8 — Real-Gmail bug fixes, reliable auto-update, rename to Fission Mail (2026-07-02)
64. **Real HTML mail rendered as plain text because `body_html` was frozen NULL** (bug 1). Root cause: `upsert_thread`'s messages `ON CONFLICT` updated only `unread`; now it refreshes content columns, healing rows an older build froze (Gmail bodies are immutable, so a non-empty re-parse is always correct — guarded with CASE/COALESCE so a good body is never clobbered by an empty one). Also: base64url decode is now padding-indifferent (the old NO_PAD engine silently dropped padded bodies), and large HTML bodies stored behind `body.attachmentId` are fetched and inlined before parsing. Fix-1 only heals on refetch, so a **Repair Mail** palette command (`resync_account`) resets the historyId baseline to force a reconcile.
65. **Input lag was the trailing `refresh()` (4 IPC) after every triage** (bug 2). Triage store actions keep the optimistic move and drop the refresh; the backend reconciles via a **debounced** `mail:updated`. Backend triage is now local-write-then-spawn-remote (returns instantly), keyboard bindings are memoized (were rebuilt every keydown), and `get_thread` returns local messages immediately with UNREAD-removal + inline-image fetches backgrounded.
66. **Two-way sync could pin a stale historyId and miss server-side removals** (bug 3). incremental refetch errors now log-and-continue so the baseline advances; 400 (not just 404) falls back to reconcile; a forced full reconcile runs on startup and every ~10 min as the inbox-removal safety net; sync cadence raised to 30s. Triage with no live session returns an explicit "account not connected" instead of a silent local-only change.
67. **The shortcut-hint footer is toggleable** (bug 4) via a palette command, persisted in `settings.showShortcutBar` (default ON, `default_true` in Rust so older state defaults ON) — mirrors the theme/calendar toggle precedent.
68. **Blank message bodies recover on open** (bug 5): `refetch_message_body` re-fetches a thread whose body is empty; MessageCard shows "Loading message…"; opening a thread sets the id immediately so J/K is non-blocking. Adjacent-thread prefetch was skipped — bodies are already local after sync.
69. **"Calendar connection error" was a mislabeled API-disabled 403** (bug 6). gmail.rs now preserves the 403 body; calendar.rs classifies it (API-not-enabled vs. missing scope vs. generic) into actionable guidance; the granted OAuth scope is captured (warns at connect if calendar was skipped); `disconnect_account` revokes server-side for true re-consent. Enabling the Google Calendar API is now a required console step in the docs — the project owner does it once for all testers.
70. **Auto-update failures were invisible** (requirement A). Every check outcome now sets a user-facing status (latest / downloading / ready / failed-retry), surfaced in the header, a Ctrl+K command, and Settings → Appearance. Checks also run on window focus (not just boot + 4h). NSIS `installMode` set explicitly to `currentUser` so the silent updater never needs UAC.
71. **Renamed ZenBox Mail → Fission Mail** (repo `email-productivity-client`). Full rename incl. bundle identifier, DB filename, keychain service, crate/lib names, `ZENBOX_*` build env, and demo domains. Migration preserves existing installs: startup copies the old `zenbox.db` from the previous identifier's app-data dir, and keychain secrets migrate lazily via a legacy-service fallback. **The updater pubkey/signing key is unchanged**, so an installed ZenBox build verifies and auto-updates into Fission Mail. The baked OAuth client env prefers `FISSION_*` but falls back to `ZENBOX_*`, and CI maps the existing repo secret, so the shared beta client keeps working without renaming repo secrets. **⚠️ Updater continuity caveat:** existing v0.7 (ZenBox) binaries have the OLD `github.com/swarnavspujari/zenbox-mail/.../latest.json` endpoint compiled in, while v0.8 publishes to `email-productivity-client`. Their auto-update into Fission relies on GitHub's permanent redirect for the renamed repo (GitHub serves these for release-download URLs). Verify out-of-band after publishing — `curl -IL` the old endpoint and confirm it 30x-redirects to a valid `latest.json` — and do NOT recreate a repo named `zenbox-mail`, which would break the redirect and strand every existing install.

## v0.9 — Design system, inbox management, local-first calendar, Unsplash, Harper (2026-07-03)
72. **The Fission Mail Design System package is the visual source of truth.** theme.css is a straight port of its tokens: midnight-navy surface ramp `#000814→#002a52`, electric-violet accent, warm-gold highlight (`--accent-2`, never on buttons), six theme-aware tag hues, four cycling sender dots, and the bottom wash. The Tailwind `@theme` contract survived the retint, so most components changed zero color code. Fission Command stays dark on ANY theme via dedicated `--palette-*` tokens that the light theme deliberately doesn't override. The real brand icon replaced the hand-drawn "Z" tile (tauri icon set regenerated from the 1056px mark; 64px copy in `public/` for the header).
73. **List navigation is list-only now** (Bug 1): `list.next/prev` gate on `inList()`, and the v0.7 follow-into-thread branch is gone — `J`/`K`/arrows are inert while reading, `Space` (new `thread.scrollDown`) pages the open message. Instant, not smooth, scrolling: keyboard paging should feel like Superhuman, and smooth-scroll also stalls in headless webviews.
74. **Command failures are never silent**: both dispatch points (key bindings and the palette) route through `runCommand`, which toasts any rejection. The mail store's `archive`/`hide` also refresh-from-DB and rethrow when the backend rejects synchronously (account not connected) — the only failure path v0.8's triage:error reconcile didn't cover (Bug 4).
75. **Multi-select is a Set in the mail store** (Bug 5): `Ctrl+A` selects from the cursor down (per the spec, not whole-list), `X` toggles a row, Ctrl/Cmd-click too. Bulk Done/Trash/Restore/Label loop the existing per-id optimistic actions and push ONE undo entry (the ZeroSweep pattern), so a single `Z` restores the sweep. Esc clears the selection before anything else.
76. **Trash is a real, synced view** (Bug 3): `trash` joined MailView (rows where `hidden='trash'`), `Delete`/`Backspace` joined `#` (saved `#` bindings migrate on read, both cores), `G`,`T` navigates, `Shift+E` restores. Reconcile gained an `in:trash` pass (cap 100): server-trashed threads hide locally; locally-trashed threads resurrect only when the server affirmatively lists them live again (absence from a capped trash listing is not proof), with the pre-listing snapshot guarding against mid-reconcile races. "Empty trash" deletions fall out via the existing refetch-404 path.
77. **Gmail label ids resolve to names at the seam** (Bug 8): a `labels` table persists each account's id→name map (refreshed every reconcile from a new `GmailSession::list_labels`), `refetch_thread` translates inbound ids before storing, and a one-time repair rewrites rows older syncs stored verbatim. Label-scoped listing rides the existing `list_threads` command as `label:<name>` (json_each, quote-safe) rather than a new command. The FolderSidebar toggle mirrors `calendarOpen` exactly (`settings.sidebarOpen`). The v0.8 Muted re-assert workaround stays — harmless belt-and-braces now.
78. **The reading pane is the design's thread screen** (Bug 9): subject as a 22px in-pane title, 760px centered measure, raised softened cards, ContactPanel (identity + FTS-driven mail history; the mock CRM button was left out — no CRM backend exists to add to). The HTML iframe bakes the current theme's token VALUES into its srcDoc (`getComputedStyle` at render; the `data-theme` attribute flips synchronously via a zustand subscription so the values read fresh) — sanitization and the script-less sandbox are untouched.
79. **Calendar mirrors the mail read/sync split** (Bugs 6-7): `list_events` is a pure SQLite read over a new `events` table; `refresh_calendar` spawns a throttled fetch (skipped when the cached window covers the range and is <2 min old) and the 30s loop refreshes a rolling -7d..+21d window every ~5 min, emitting `calendar:updated` (payload = classified error or null). The per-calendar fetch resolves the token once and hits all calendars concurrently. Day state lives in a shared day-keyed store so the panel paints instantly on reopen; `←`/`→` are gated on a two-value `focusRegion` (week view screen, or the open+focused day panel) so arrows are never swallowed in the list. The deferred-since-#62 week view shipped (`G`,`C`).
80. **Daily Unsplash photo on empty splits** (backend-only key): keychain `unsplash:access_key` (BYO via Settings → Appearance) overrides `option_env!(FISSION_UNSPLASH_ACCESS_KEY)`; the key never reaches the web bundle. Guidelines followed literally — hotlinked `urls.regular` with its ixid, blur-hash placeholder (dependency-free decoder), download_location fired once per photo on first show, utm-tagged attribution. 24h cache keeps metadata + bytes (offline data: URI fallback), stale-if-error, and a ≤50 req/hour token bucket guards the cap. ⚠️ Owner action: run `gh secret set FISSION_UNSPLASH_ACCESS_KEY` once (the build agent's permission gate blocked repo-secret writes) — release.yml already reads it; until then releases ship without the baked key and the local keychain copy covers dev builds.
81. **Harper checks compose locally** (harper-core, `concurrent` feature — LintGroup isn't Send without it): `lint_text` runs the once-built curated linter on the blocking pool and returns UTF-16 spans so the UI never re-maps offsets. The UI is a transparent-text backdrop mirroring the textarea (wavy `--danger` underlines), with a caret-in-span suggestion bar — apply-on-accept, never auto-replace. The browser mock lints against a small fixture list so the demo exercises the same flow.
82. **Demo fixtures grew user labels** (Deals/LPs on three threads, TS + Rust in parity) so label views and the sidebar have real content to show without a connected account.
83. **Recipient autocomplete is derived from synced mail, not the People API.** A `contacts` table (account_id, email PK, name, freq, last_seen) is filled from every message's sender + recipients as mail syncs (indexed only on first-seen messages so freq counts distinct messages, not re-syncs), with a one-time backfill in `store::open` (kv-gated `contacts_built_v1`) so existing installs get an index immediately after updating. `search_contacts(query)` ranks prefix-on-name/email first, then freq, then recency, excluding the account's own address. The To/Cc fields autocomplete the token straddling the caret and insert `Name <email>` (accepted by the send validator, which only checks for `@`). This deliberately avoids the Google Contacts/People-API scope (DECISIONS #56 declined it — more consent friction than it's worth) while covering the real use case: everyone you actually email. If true address-book sync is ever wanted, it's a new OAuth scope + owner re-consent decision.

## v0.16.0 — Calendar two-way sync: event CRUD, invites, RSVP-from-mail (2026-07-07)

97. **The events cache table was dropped and recreated, not ALTERed** — the one deviation from the guarded-ALTER migration precedent (v0.2/v0.3/v0.5/v0.13), recorded per the spec's §9.2 open item. The full event model (description, htmlLink, etag, status, organizer, recurringEventId, hangoutLink, attendees JSON, calendarId + display name, accessRole, iCalUID) needed eleven new columns *and* a new PRIMARY KEY `(account_id, calendar_id, id)` — the old `(account_id, id)` can't key per-calendar sync upserts because the same Google event id exists on every attendee's calendar — and SQLite can't ALTER a primary key. Since `events` is a pure cache the next sync beat rebuilds, `open()` detects the old shape (no `calendar_id` in `pragma_table_info`) and drops it; stale `cal_window:` bookmarks are cleared with it. Reads dedup the same event id across calendars toward the most-privileged copy (owner > writer > reader) so shared calendars don't paint duplicates.
98. **Per-calendar syncToken engine under unchanged read shapes.** Each calendar syncs independently (kv `cal_sync:{email}:{calendarId}`): initial pass = windowed full fetch (-30d..+365d, `singleEvents=true`, paged) capturing `nextSyncToken`; every later pass sends only `syncToken` + `singleEvents` + paging (`orderBy`/`timeMin`/`timeMax` are invalid with a token), applying upserts and `status=cancelled` tombstone deletes; **410 Gone drops the token, clears ALL the calendar's rows (a deletion inside the token gap would otherwise zombie forever), and refetches the window**. `calendarList` accessRole/primary land on every cached event for UI gating; calendars that vanish from the list are pruned; per-calendar failures don't blank the rest (an error surfaces only when nothing synced). Cadence: the 5-min background beat (forced), UI-triggered `refresh_calendar` (now token-cheap, throttled to one pass/min), a new window-focus refresh, and a forced pull after every local write. `list_events`, `refresh_calendar`, and `calendar:updated` kept their exact shapes; only the internals changed. Disconnect now also clears the account's events + syncTokens so a reconnect starts clean.
99. **Writes are direct Google calls with If-Match etags — deliberately no offline queue (v1, per spec non-goal).** `create_event` / `update_event` / `delete_event` / `rsvp_event` send `If-Match` on update/delete; a 412 crosses IPC as `{status:"conflict", event:<fresh server copy>}`: the modal shows "This event changed elsewhere — review and retry" with Load-latest re-arming the form on the new etag; delete conflicts reopen the popover on the fresh copy. Success upserts the response locally, emits `calendar:updated`, and kicks an incremental sync. Guest notifications: any save/delete touching a guest list prompts Send / Don't send (→ `sendUpdates=all|none`); RSVP always notifies the organizer. RSVP patches the **full attendee array** with only the self row's `responseStatus` flipped — the attendees array overwrites wholesale, so a partial patch would drop the other guests — and update merges the cached attendee records back in for the same reason (bare emails would reset everyone's RSVP to needsAction).
100. **Calendar UI: modal + popover, Superhuman-keyed.** Click/drag on empty grid slots (30-min snap, plain click = 1h) opens the create modal prefilled; `B` = New Calendar Event (Superhuman's Create Event key — the spec's `c`-collision concern resolved by parity rather than a context chord); clicking an event opens a popover with time/location/Meet link/description/guest RSVP states. Affordances gate on the model: invited events (self attendee, organizer ≠ self) get RSVP Yes/Maybe/No; owned or guestless-writable events get Edit/Delete (with a notify-guests step when guests exist); reader/freeBusyReader calendars render as before with no edit surface. Declined events fade + strike through, pending invites render dashed. All-day events keep Google's exclusive-end date convention end-to-end (the modal displays the inclusive last day).
101. **Invite mail → RSVP bar via a captured ICS + iCalUID resolution.** Sync now captures the raw iCalendar payload (bare `text/calendar` part or invite.ics attachment — attachment-backed copies hydrate inline via the existing body-hydration pass) into `messages.ics_data` (guarded ALTER, 128 KB cap). A ~120-line tolerant reader (`mail/ics.rs`) pulls METHOD/UID/SUMMARY/ORGANIZER/DTSTART/DTEND/URL from the first VEVENT — deliberately not a full RFC5545 parser: no suitable iCal crate was already in the tree, and TZID-zoned times are approximated as local wall-clock because they only label the bar — **RSVP acts on the resolved Google event**, whose times are authoritative. Resolution: local `ical_uid` index first, then remote `events?iCalUID=` across calendars primary-first (no singleEvents, so a recurring invite resolves to its series master and one RSVP covers the series, like Gmail's own buttons). Unresolvable invites fall back to "Open in Google Calendar" (the ICS `URL:` when present); METHOD:CANCEL renders an informational strip. Invite mail synced before v0.16 has no captured ICS until its thread re-syncs (`ics_data` heals via COALESCE on upsert); the existing resync repair covers the backlog.

Fixture events grew organizer/attendee data — the board meeting arrives as a pending invite so RSVP affordances are demoable everywhere.

103. **Review round (8-angle finder pass, 43 candidates; 24 fixed, the rest refuted or accepted).** Fixed highlights — *sync correctness:* a Google syncToken permanently encodes its initial fetch's time bounds, so the engine now re-anchors (drops tokens + refetches) every 30 days to roll the -30d..+365d horizon forward, and navigating outside the window triggers a one-off range fetch with the old coverage-bookmark throttle (without either, dates past the horizon were permanently blank); ## Search Phase 4 — semantic/vector search (2026-07-09, branch `claude/fission-search-ranking-e6cbfd`)

(Ledger note: search Phases 1–3 — full-history crawler, weighted bm25, NL planner — shipped straight to `main` on 2026-07-09 (`c0bdedf`) without a DECISIONS section; their choices live in the commit message and `docs/FOLLOWUP-PROMPTS.md`. This section records the deferred semantic tier, built per the Phase 4 prompt there.)

105. **Vector store: sqlite-vec 0.1.9, statically linked into the existing rusqlite `bundled` — Typesense stays rejected.** One `mail_vec` vec0 table (`embedding float[384] distance_metric=cosine`, rowids paired to a plain `vec_meta` bookkeeping table: message_id/thread_id/account_id/model). The mirror table exists because a vec0 vtab can't be LEFT-JOINed efficiently for "which messages still need embedding", and it carries the deletes (thread delete + healed-body re-embed both drop vectors; the beat re-adds). Writes are DELETE-then-INSERT — stable sqlite-vec has no upsert (0.1.10-alpha only). KNN is brute force in 0.1.9 (ANN is alpha-only): single-digit ms at 10⁴–10⁵ vectors × 384 dims, fine for a mailbox and no alpha-quality risk. Registration is the process-global `sqlite3_auto_extension` hook, `Once`-guarded in `store::open` so tests get vec0 too.
106. **Embeddings: local by default — fastembed 5.17.2 running quantized `bge-small-en-v1.5` (384-dim) on CPU.** Chosen over MiniLM-L6-v2 (MTEB retrieval 51.7 vs 42.0 at the same dims; ~34 MB vs 23 MB quantized — measured cache incl. tokenizer: **65 MB**) and over raw `ort`/candle (fastembed bundles tokenization/pooling/normalization; candle is slower on CPU). bge needs its retrieval instruction prepended to **queries only** — fastembed does not add it; `embed::QUERY_PREFIX` does. ONNX Runtime binaries are **statically linked** on Windows (verified: no onnxruntime.dll in the build tree) → nothing added to the Tauri bundle config; expect +25–35 MB release exe, a build-time ~29 MB fetch from cdn.pyke.io, and never enable `+crt-static` (pyke libs are /MD). The model lives in `app_data/models` (fastembed's default cache dir is cwd-relative — a Tauri trap), downloads in the background on the first embed beat (~3 s on a fast line), retries no sooner than 10 min on failure, and **a search never waits on it** — the semantic leg just stays off until Ready. Optional `settings.embeddings = "openai"` routes to `text-embedding-3-small` with `dimensions=384` through the stored OpenAI key (**Anthropic has no embeddings API** — the remote path is never Claude); the kv `embed_model` tag wipes and re-embeds all non-demo vectors on any local↔remote/model switch, since vectors from different models don't share a space.
107. **Retrieval: hybrid via Reciprocal Rank Fusion inside `store::search_planned`'s term route.** Both legs run the same account/hidden/date/people narrowing; each contributes 1/(60+rank), so a dual-leg (exact-term) hit always outranks a same-rank semantic-only neighbor — semantic **extends recall below** exact matches, never displaces them (property pinned by test). The vector leg is capped at 20 threads (brute-force KNN always returns k rows however weak; the cap bounds the "nearest neighbors" tail), over-fetching k=240 message-level before thread aggregation. `qvec = None` — model absent/downloading, per-keystroke path, empty terms — is **byte-identical to the old lexical SQL** (all five pre-Phase-4 search tests unchanged). Embedding beats ride the existing crawl spawn and busy-guard (one mechanism backfills old mail and keeps up with new: "messages with no vec_meta row, newest first"), budgeted at 4 s/beat, batches of 32 in single transactions, inference on a blocking thread behind `Arc<Mutex<TextEmbedding>>` (fastembed's `embed` is `&mut self`). Only `search_all` embeds the query — exactly one small inference per search, never per keystroke; `search_threads` (instant) stays lexical. `search_all`'s final date-sorted remote merge is pre-existing Phase 1–3 behavior and was deliberately left untouched (semantic recall = membership; noted for the owner as a possible future rank-preserving merge).

## Reading pane: inline shadow-DOM body render (2026-07-09, branch `claude/fission-mail-reading-pane-bfc8f7`)

Replaced the sandboxed `<iframe srcDoc>` email body (`HtmlBody` in `src/features/thread/ThreadView.tsx`) with an inline **shadow-DOM** render in the app document, so the reading pane reads as one continuous document like Superhuman's. Fixes the four iframe-caused bugs at once and removes the sandbox as a trust layer, so the change is as much security as visual.

109. **The iframe is gone; the body renders in a shadow root in the same scrolling document as the subject.** Root cause of all four reported bugs was the `<iframe sandbox="allow-same-origin">`: (a) selection can't cross the iframe boundary, (b) height is measured after load + re-measured on 150/500/1200 ms timers + a ResizeObserver, so stepping between emails visibly reflows, (c) wheel events over the iframe don't chain to `[data-thread-scroll]`, (d) the srcDoc wrapper made preheader/duplicate-subject stripping impossible from the parent. A shadow root (`host.attachShadow({mode:"open"})`, one per message) scopes the email's CSS both ways — the email's own `<style>` can't leak into the app chrome, app CSS can't restyle the email — while native selection, one native scroll, and CSS-custom-property inheritance all pass through the boundary. Selection crossing subject→body verified via `getComposedRanges` (startContainer in the app document, endContainer in the shadow tree) and a real clipboard copy containing both. **No height measurement at all** — the shadow content lays out at its true height synchronously, so there's zero reflow when switching emails (the entire timer/ResizeObserver/`setHeight` machinery deleted). Thread-open scroll is now deterministic off real heights (single message → top; conversation → top of the latest message).
110. **Containment jail: `contain: layout paint style` on the light-DOM wrapper is the second isolation layer.** Shadow DOM scopes *selectors* but does NOT stop a `position:fixed` element inside from painting over the app toolbar (fixed escapes the shadow host's normal flow). The wrapper `<div style="contain:layout paint style">` establishes a containing block + paint-clip so even a surviving fixed/absolute element is jailed to the message box. Verified adversarially: injected a `position:fixed;inset:0;width:100vw;height:100vh;z-index:max` overlay into the shadow root — it clipped to the wrapper rect (85,229,699,284), and hit-testing the toolbar/sidebar/contact-panel still returned app chrome (IMG/NAV/"Fission Mail"), not the overlay. Belt-and-suspenders with the sanitizer's CSS scrub (#111), because `contain` alone wouldn't stop a fixed element that's visually *inside* the pane from covering other messages.
111. **Removing the sandbox makes the Rust `sanitize_email_html` the SOLE active-content trust boundary — hardened accordingly.** The sandbox used to be "the second layer" (its own doc comment); now there's no second layer for scripts/handlers/forms, so the sanitizer must catch everything. Added, TDD (17 render tests, all green): **`<style>` is now KEPT** (newsletters need it; ammonia default deletes it — flipped via `add_tags(["style"])` + `rm_clean_content_tags(["style"])`) but its CSS is **scrubbed**; `class`/`id` allowed so kept rules can target elements. The CSS scrubber (`scrub_css`, run over both `<style>` text and every `style=""` attribute via `attribute_filter`) drops `position:fixed|sticky`, `@import`, and legacy execution vectors (`expression()`, `behavior:`, `-moz-binding:`), and neuters any selector containing `:host` (an email `:host{}` rule would otherwise restyle the shadow host from inside). It decodes CSS escapes on a throwaway match-copy so `\70osition:\66ixed` and `position/**/:/**/fixed` obfuscation can't smuggle a fixed overlay past; strings and `url()` bodies are masked so bans can't fire on their content and original bytes are emitted verbatim (no corruption of legitimate escaped selectors). Per-attribute URL policy on top of the scheme allowlist: `href` = http/https/mailto/tel only (kills `data:text/html` link navigations), `src`/`background` = http/https or `data:image/*` only, `srcset` = http(s) only. Forms/inputs/iframe/object/embed/meta/base stay stripped (existing ammonia behavior, now pinned by tests). Desktop CSP tightened as the third layer: added `form-action 'none'; base-uri 'self'`.
112. **Preheader + duplicate-subject stripping (`src/lib/email-render.ts`, `prepareEmailHtml`, happy-dom tests).** What the srcDoc approach couldn't do from the parent, a DOMParser pass now does before injecting into the shadow root — Superhuman-style. **Preheader:** walks leading nodes in document order and removes inline-hidden (`display:none`, `visibility:hidden`, `font-size≤2`, `max-height≤1`, `opacity≤0`, `mso-hide:all`) or all-invisible-character padding blocks (`&zwnj;&nbsp;…`) until the first visible content; tracking pixels (≤2px) are scanned past, not treated as content; a short `&nbsp;` spacer stays. Class-hidden preheaders (`.preheader{display:none}` in the email's own kept `<style>`) are looked *through* (they render invisible via the kept CSS) but never removed — a static parse can't prove no override reveals them; `@media`-conditional hiding does NOT count as hidden. **Duplicate subject:** first message only, climbs to the largest ancestor with the same text, matches subject exactly or as a prefix the subject extends (after stripping re:/fwd: and normalizing case/punctuation/emoji), and refuses to remove if it would leave the message with <40 chars of visible text and no image — a false positive that hides a real heading is worse than the echo.
113. **Dark-theme canvas for "designed" mail.** Mail that declares its own colors/backgrounds (`/color\s*[:=]|background[^;:=]*[:=]/`) is authored against white; on the dark theme it would render dark-on-dark. Such mail gets `data-light-canvas` → a forced white canvas + `color-scheme:light` in the shadow `:host` (Superhuman does the same). Bare mail (plain replies, no color declarations) inherits the app's theme tokens and looks native in both themes. Caught in review when the GitHub fixture first rendered dark-on-dark — the initial heuristic only checked `color`/`bgcolor`, missing `background:`.
114. **Mock parity + fixtures exercise the new path.** The demo mock (`src/lib/mock.ts`) already renders `bodyHtml` through the same `HtmlBody`, so it's covered by construction. Gave two fixtures real bodies that stress the rework: `t-newsletter-lenny` (a `<head><style>`, a class-hidden preheader, an inline-hidden `&zwnj;` pad run, and a hero `<h1>` duplicating the subject — all three stripped at render) and `t-github` (a long single-line `<pre>` + a fixed-width `nowrap` table that must scroll in their own boxes, not widen the pane). **Verified in the browser demo (port 1420)** via Playwright: subject→body drag selection crosses the boundary (screenshot + `getComposedRanges` + clipboard), zero iframes in the DOM, wheel-over-body scrolls the pane (scrollTop 0→37), both newsletters render on a light canvas with the preheader/hero gone, wide GitHub content scrolls in its own box with the pane un-widened (`scrollWidth ≤ clientWidth`), and the `position:fixed` overlay attack stayed jailed. `cargo test` (40 lib + 17 render), `npm run build` (tsc), and `vitest` (54) all green. **Owner desktop E2E still open:** real Gmail HTML through the desktop webview (WebView2/WKWebView shadow-DOM + `contain` parity), remote-image loading, `cid:` inline images inline-rendered, and the CSP change on a packaged build.

## Uninstall cleanup — credentials, legacy orphans, attachment cache (2026-07-25, branch `claude/snail-mail-uninstall-cleanup-168961`)

122. **Secrets are purged unconditionally; mail stays checkbox-gated.** Tauri v2 has no `deleteAppDataOnUninstall` (verified against `tauri-utils` 2.9.3), and the stock NSIS template puts data deletion behind a checkbox that is **unchecked by default**, scoped to `$APPDATA\${BUNDLEID}` + `$LOCALAPPDATA\${BUNDLEID}` + the vendor registry keys. That checkbox is a reasonable question to ask about a 5 GB mailbox, so `NSIS_HOOK_PREUNINSTALL` does not second-guess it and never deletes those paths. It *does* purge, with no checkbox: (a) every OS-keychain entry, and (b) the legacy-brand orphans. Rationale: **leaving mail behind is a preference, leaving a live Google refresh token behind is a security bug.** Before this, an uninstall — ticked or not — left `gmail:refresh_token:<email>`, the OAuth client secret and every AI key sitting in Windows Credential Manager forever, because NSIS cannot reach the credential store at all.
123. **The uninstaller borrows the app binary: `snail-mail.exe --purge-data`.** Credential entry names are derived from the account list *inside the databases*, and only the binary can read both. `purge::maybe_run_cli` intercepts the flag at the very top of `run()` — before `tauri::Builder`, so no window, no webview, no DB connection — and the hook calls it with `ExecWait` from `NSIS_HOOK_PREUNINSTALL`, which is the first statement in `Section Uninstall` (verified in the generated `installer.nsi`), i.e. before any file is deleted and while `$UpdateMode` is already parsed. Tokens are handed to Google's `/revoke` before deletion, so uninstalling ends the grant rather than merely forgetting it. Everything is best-effort and bounded (~15 s worst case on a dead network): an uninstall must never hang or fail on a locked file. Flags: `--all` (also this install's mail/models/caches — what the in-app button uses), `--dry-run`, `--no-revoke`, `--no-credentials` (diagnostics only), `--app-data`/`--app-cache` overrides.
124. **`$UpdateMode` is the single most dangerous line in the hook.** Every auto-update runs this same installer with `/UPDATE`, so the whole macro body sits inside `${If} $UpdateMode <> 1`. Without that guard the cleanup would fire on every release.
125. **In-app "Erase all local data" (Settings → Privacy & keys → On this machine).** The research prompt said "Account area", but the settings redesign made Accounts a *per-address* scope while this is app-wide and machine-scoped — it belongs next to "Resync from scratch" and "Local mail cache" in Privacy, which is also where every credential is already surfaced. Three steps to fire (arm → type `ERASE` → confirm) because there is no undo for a deleted credential, and the result renders as a **literal list of what was removed**, keychain entries named by `<service>/<entry>` — for a security action the receipt *is* the feature. `global.db` is emptied (`DELETE FROM kv`) rather than unlinked, because its connection is open and Windows will not unlink a mapped file; the result is byte-for-byte the state a fresh install boots into, with no restart. Refused while the per-account split migration is in flight.
126. **Deleting a directory is never "remove the root".** The purge names every file it knows (`fission.db`+`-wal`/`-shm`, `zenbox.db*`, `global.db*`, `accounts/`, `models/`, `attachments/`, `EBWebView/`) and only removes a root once it is *already empty*. A tree containing something this build does not recognise is left alone — silently `RMDir /r`-ing an app-data root is how you delete someone else's data. Pinned by `a_root_with_unknown_files_is_kept`.
127. **`dev-secrets` is gated behind its own cargo feature.** Cargo auto-discovers `src/bin/*.rs` and tauri-cli bundles every discovered bin as an *external binary* — confirmed in the generated installer: `File /a "/oname=dev-secrets.exe" …`. A keychain-**writing** developer utility was therefore shipping inside every installed app directory. Declaring it as an explicit `[[bin]]` with `required-features = ["dev-secrets"]` takes it out of every default build, so `cargo build --release` never produces the exe and the bundler has nothing to pick up. **Gating alone would have been a regression**, though: an auto-update never runs the old uninstaller (`PageLeaveReinstall`: "In update mode, always proceeds without uninstalling"), and the new uninstaller has no `Delete` line for a file the new bundle no longer contains — so every already-installed copy would have survived every future update *and* every future uninstall, and the leftover would additionally have made the template's non-recursive `RMDir "$INSTDIR"` fail. `NSIS_HOOK_POSTINSTALL` therefore deletes `$INSTDIR\dev-secrets.exe` explicitly (it runs on updates, unguarded by `$UpdateMode` — that is precisely the stranding path), and `NSIS_HOOK_PREUNINSTALL` repeats it outside its own update guard.
128. **The attachment cache is keyed by attachment id, not filename, and is pruned at boot.** The old flat `attachments/<sanitized-filename>` layout meant every `invoice.pdf` on the machine was the *same file* — opening one attachment silently overwrote another, and account removal deleted a name a different account still pointed at (the old code carried a whole cross-account "is this name still referenced" filter to paper over it). Entries are now `attachments/<attachment-id>/<real-filename>`: collision-free by construction, the user still sees the sender's filename, removal is a single `remove_dir_all`, and the cross-account filter is deleted. Nothing in the cache is authoritative — every byte is re-derivable from the mailbox — so a boot-time prune drops entries older than 14 days and then evicts oldest-first past a 256 MB cap. Pre-fix flat files age out through the same policy rather than being special-cased.

## v0.23.0 pre-release audit — cross-track seam fixes (2026-07-25, main)

129. **Classifiers take split definitions as a parameter; they never read them off an ambient connection.** `store::split_config(conn)` read `kv['settings']` from whatever connection it was handed. That was correct until the per-account re-architecture landed on top of Split Inbox v2 — after it, the connection handed to `upsert_thread`/`reclassify_page` is the *account* file (or the legacy db mid-migration), and `settings` is a `GLOBAL_KV_KEYS` entry that only ever exists in `global.db`. Classification therefore fell back to `default_settings().splits` (Important + Other) and **every custom split silently classified nothing on desktop** — while the editor's own `preview_split` parsed the query directly and cheerfully reported matches. Both tracks were individually correct and individually tested; the whole cargo suite passed because its tests put settings and threads on one in-memory connection. Fix: `DbRegistry::split_defs()` is the single authoritative read (global.db), and `upsert_thread`/`reclassify_page` now require a `&[Split]` argument, so the mistake is no longer expressible. `split_defs_read_global_settings_and_classify_account_threads` pins both directions — including the assertion that an account conn does *not* see custom splits, which will fail loudly if the global/account separation ever changes.
130. **Migration bookkeeping is cleaned only after the migrated flag is durable.** `flip_small_tables` deleted the `migrate_cursor:*` keys inside the flip transaction, but `reg.mark_migrated()` runs *after* that transaction commits — and `verify_account` (COUNT(*) joins over a multi-GB attached legacy db) sits between them. A kill in that window left: all rows copied and flipped, cursors gone, flag absent. Resume then restarted the bulk copy from rowid 0, and while `messages`/`attachments`/`vec_meta` use `INSERT OR IGNORE`, `mail_fts` and `mail_vec` are plain `INSERT` on explicit rowids — so the migration **wedged permanently, on every subsequent boot**. Fix: cursors survive the flip and are deleted after `mark_migrated` (best-effort — a leftover cursor key is inert). Re-running the flip is safe by construction: all seven `FLIP_TABLES` have primary keys and use `INSERT OR REPLACE`. `kill_between_flip_and_mark_migrated_resumes_clean` reconstructs that exact on-disk state and resumes. The pre-existing resume test could not have caught this: it simulates kills via `MigrateOpts.max_chunks`, whose budget check sits inside the bulk-copy loops and therefore can only ever stop *before* the flip.
131. **A purge that does not know about `fission.db.bak` erases nothing.** The split migration renames the legacy single-file mailbox to `fission.db.bak` and keeps it until every account verifies (#2's safety net). `purge::data_targets` enumerated `fission.db`/`zenbox.db` plus `-wal`/`-shm` — not the `.bak`. So on any machine where the split had finished but the next boot had not yet reaped it, both "Erase all local data" and the uninstaller's `--purge-data --all` left a complete copy of every account's mail, bodies and attachments on disk. Worse, it became *unreachable*: the in-app erase clears the `migration_done` flag that `delete_bak_if_verified` gates on, so nothing would ever remove it again. The non-recursive root cleanup (#126) is deliberately not a fallback here. Fixed in `data_targets` (`.bak`, `.bak-wal`, `.bak-shm`) and pinned in `data_targets_cover_every_db_sidecar` for both `include_global` variants.
132. **`$UpdateMode` does not cover a manual installer-over-installer upgrade.** #124 guarded the credential purge on `$UpdateMode`, which is correct for the auto-updater — but the auto-updater, per `PageLeaveReinstall`, never runs the old uninstaller at all. The path that *does* run it is a manual re-install: the template's reinstall page defaults to "Uninstall before installing" and `ExecWait`s the installed uninstaller **without** `/UPDATE`. So a routine manual upgrade would have revoked every Google grant and wiped Credential Manager mid-upgrade. Every such invocation appends `_?=<instdir>` (visible in `reinst_uninstall` in the generated `installer.nsi`), which a terminal uninstall from Add/Remove Programs never carries — so the hook now also skips the data purge when `_?=` is present. Two independent guards, because the failure is silent and unrecoverable.
133. **The badge refreshes on the actions that actually change it.** `refresh` hung off `emit_mail_updated`, which was described as the funnel every producer goes through — but the single-thread triage commands (`mark_read`, `mark_unread`, `archive_thread`, `snooze_thread`, `hide_thread`, `restore_thread`, `mute_thread`, `move_to_inbox`, star, label) write their column and hand off to `spawn_remote` *without* emitting it; the front end updates optimistically and the count only caught up at the next 30 s sync tick. Those are precisely the actions that move an unread count. `spawn_remote` now refreshes the badge as its first statement — still one choke point, but the right one. `refresh` also gained newest-wins sequencing (an atomic generation counter) so two concurrent recounts cannot paint out of order.
134. **CI runs the tests it has.** Before this release no CI job executed a single test: `build.yml` was `tsc` + `vite build` + `cargo check`, and `release.yml` ran none — the ~340 tests added across the usage pass only ever ran on the owner's machine. The Windows job now runs `npm test` and greps the built desktop bundle for fixture strings (guarding the build-time mock split, which no CI job previously exercised); the Linux job runs `cargo test --features demo-fixtures`, which also keeps the demo-fixture code compiling. Two tests had to be unpinned to make Linux honest rather than green-by-luck: `everything_scope_takes_the_mailbox_models_and_caches` asserted a `-wal` sidecar appears in the deletion *report*, but `known_emails` opens each db (`open_ro` falls back to read-write) and SQLite checkpoints and unlinks a stray `-wal` on close, so on Linux the purge correctly finds it already gone — the assertion now checks the end state, with enumeration still pinned by `data_targets_cover_every_db_sidecar`. The four `secrets` tests that *write* to the OS credential store are `#[cfg_attr(target_os = "linux", ignore)]`: a headless runner has no `org.freedesktop.secrets`. **That leaves them with no CI coverage at all** — they run on Windows/macOS dev machines only, and restoring real coverage (gnome-keyring under `dbus-run-session`, or `cargo test` on the Windows job) is tracked as follow-up work.
135. **CI gets a real Secret Service rather than skipping the keychain tests.** #134 ignored the four credential-store tests on Linux; that left the chain the uninstall purge depends on (primary service + `FissionMail`/`ZenBoxMail` fallback + copy-forward) with no CI coverage anywhere. `keyring`'s `sync-secret-service` feature resolves to `dbus-secret-service` 4.1.0, so `org.freedesktop.secrets` is genuinely the Linux backend the app ships — meaning gnome-keyring under CI is the real thing, not a stand-in. The linux job installs it and runs the whole suite inside **one** `dbus-run-session` (the daemon registers on that bus and dies with it, so splitting it across steps cannot work). Two guards keep the step honest, because the failure mode being removed is *silence*: it waits for the bus name and fails loudly if it never appears instead of running storeless, and a following step asserts each of the four tests ran **by name** — so a future change that re-ignores or renames them cannot pass green. Linux now reports the same `130 passed; 5 ignored` as a Windows dev machine.

## v0.24.0 — reconciling three parallel tracks (2026-07-25)

136. **Per-account storage means per-account *addressing*, not just per-account files.** v0.23.0 gave every account its own SQLite file but left `drafts` and `outbox` keyed by a bare `INTEGER PRIMARY KEY AUTOINCREMENT` — unique only *within* one file. Four command paths resolved those ids by probing account connections active-first and taking the first hit (`delete_draft`, and `outbox_db` feeding `cancel_outbox`/`send_outbox_now`); `save_draft` did not probe at all and updated the *active* account's row. With two accounts connected, id 7 minted under B is shadowed by id 7 under A. `save_draft` was the worst: compose autosaves every 800 ms, so one keystroke after an account switch silently overwrote the wrong mailbox's draft. Identity is now the pair `(id, account_email)` carried across IPC, and every id-addressed store mutator scopes on `account_id`. Note *why* resolving the connection is not sufficient on its own: mid-migration `DbRegistry::account` hands several accounts the same legacy db, so the discriminator has to be in the `WHERE` clause, not in the choice of handle. Pinned by two seeded account files both holding id 7.
137. **The sweep's selection predicate is the tab's count predicate, in the same file.** `bulk_archive` selected from `inbox_threads_for_sweep` → `list_threads`, which carries `LIMIT 500` — a *display* window — and then filtered it in Rust, while the split tab beside the button counted the whole mailbox via `store::split_counts`. Above 500 conversations the two disagreed permanently: one sweep archived 500 and the tab still read four figures. The fix is not "raise the limit"; it is that `SweepFilter::where_sql` is `split_counts`' predicate, so the number shown and the number moved are the same number *by construction* rather than by two implementations happening to agree. The preserve options moved into that predicate too — as a post-filter over a page they could only ever mean "absent from the rows we looked at". Pinned by `sweep_drains_a_split_larger_than_the_display_window` (600 threads, one drain, tab at zero).
138. **A catch-all sweep must take `split_id IS NULL`.** Rows the classifier has not reached carry NULL, and `threadInSplit` folds them into the catch-all — so that is where the owner *sees* them. A sweep matching only `split_id = 'other'` would leave exactly those on screen right after claiming to empty the tab. `SweepFilter::include_unclassified` adds the branch, and `bulk_archive` sets it by resolving the requested split against the new `splits::catch_all_id` (mirroring `catchAllSplitId` in split-query.ts). Note the *pre-existing* half of this seam is untouched: `split_counts` tallies NULL under key `""` while `MailScreen`'s `countOf` reads `splitCounts[id]`, so the catch-all tab still undercounts rows its own list shows. Post-sweep state is consistent; the pre-sweep count is not, and fixing it means teaching `split_counts` which split is the catch-all.
139. **The Gmail half of a sweep is a durable queue, not a spawned loop.** Archiving locally is instant; archiving on Gmail is one `modify_thread` per thread, and a whole-split sweep can owe tens of thousands. The old code spawned an in-memory loop — which the app outlives only by luck. That matters more than it sounds: `refetch_thread` rebuilds `in_inbox` from Gmail's labels, so every request that never went out becomes a thread reconcile drags **back** into the inbox, and the sweep appears to undo itself hours later. The new per-account `remote_ops` table is shaped deliberately like `outbox` (claim before the network call, 5-attempt cap, dead-grant parking that doesn't burn attempts, released on reconnect) and is drained beside it. `sweep_once` writes the local archive and the queued op **in one transaction** — split them and a kill in between recreates the exact stranding the queue exists to prevent. Enqueueing supersedes any *unclaimed* op for the same thread, so undo cannot be re-archived by a drain still working through the sweep.
140. **A sweep that outgrew the window outgrew its undo.** `ZeroSweep.tsx` predicted the swept set by filtering `m.inbox` — the same 500 rows — while the toast promised "Z restores all". Correct only while the sweep was equally blind. `bulk_archive` returns `BulkArchiveResult { archived, ids }` now and undo calls a chunked `bulk_move_to_inbox(ids)`: one IPC round trip instead of one per conversation, and exact at any size. The prediction (and its `threadInSplit` import) is deleted rather than kept as a fallback — a second, differently-wrong definition of "what got swept" is what caused this.

## v0.24.1 — the empty-secret auth outage (2026-07-26)

141. **A set-but-empty build env is absence, and `Some("")` is the bug that hides that.** Every account showed "Google sign-in expired" and Reconnect died on Google's own page: *"Error 400: invalid_request — Missing required parameter: client_id"*. Nothing was wrong with the tokens. `release.yml` passes `SNAIL_GMAIL_CLIENT_ID: ${{ secrets.ZENBOX_GMAIL_CLIENT_ID }}`, that secret **has never existed on the repo** (`gh secret list` shows only the two Tauri signing keys), and **GitHub renders a missing secret as an empty string rather than leaving the variable unset** — so `option_env!` returned `Some("")` and `BAKED_GMAIL_CLIENT_ID` was present-but-blank in every published installer. `Some("")` is the worst possible value here because it is truthy to both checks that guard this path: it satisfies `.is_some()`, so `has_gmail_client()` returned true and the Add-account pane told the owner *"Your OAuth client is already in the Credential Manager — leave the fields blank and hit Connect"*; and it defeats `.or_else()`, so no fallback ever ran. The blank id went out as `client_id=`, and Google's reply blamed the request rather than the app that malformed it. Fixed with a `const fn present()` that collapses empty to `None` at every `option_env!` site (Gmail id, Gmail secret, and the Unsplash key — which had the same latent hole on its baked arm while already filtering its keychain arm), a `stored_secret()` that does the same for keychain reads (`start_oauth` used to persist whatever it resolved, so one run with a blank baked client could write `""` over a working entry), and a final explicit guard before the consent URL is built. Pinned by `baked_credential_tests`. **The published installer still ships no OAuth client** — that is a repo-secret configuration gap, not a code one; the app now says so plainly instead of producing a Google 400.
142. **The message explaining why every mailbox is frozen does not get a 2.6-second toast.** `reconnectDead` caught its error and passed it to `showToast`, so the one string identifying the failure vanished before it could be read — the owner's report was literally "it threw an error which I didn't catch". Reconnect failures now render in a persistent, selectable strip under the account banner with an explicit Dismiss, so the text can be read, copied, and pasted into a report. The transient surface was right for optimistic triage and wrong for an outage.
143. **Half a baked client fails the build, because it cannot fail honestly at runtime.** With #141's `present()` in place, a blank credential correctly reads as "no client configured". But an id set *without* its secret is indistinguishable from that at runtime — the app would say "no OAuth client" while the repo believed it had one, and the misconfiguration would live on undetected across releases. `release.yml` therefore asserts the pair is whole-or-absent before building. The secrets also moved off their `ZENBOX_*` names onto `SNAIL_*`: the indirection was justified in a comment as avoiding repo reconfiguration, but the legacy secrets had never existed, so it protected nothing and made the empty-string default look intentional. Validated end to end rather than by inspection — the live client returns HTTP 200 and Google's sign-in page for the exact URL `run_flow` builds (which also proves it is a Desktop-type client, since a Web client rejects the loopback `redirect_uri`), and the same request with `client_id=` reproduces the reported "Missing required parameter: client_id" verbatim.

## v0.25.0 — usage pass (2026-07-26)

144. **"Expired or was revoked" is a claim, and it was being made about credentials that were simply gone.** A dead grant and an absent token both surface as `connected: false`, and the banner asserted revocation for both — which sent a real debugging session hunting Google-side causes for hours while the actual cause was a local deletion (the uninstall E2E had purged the keychain, by design). `has_stored_grant` answers "is there anything to refresh with", and the banner words itself accordingly. The unknown state deliberately falls back to the *revoked* wording: telling someone a credential is MISSING when it is merely refused sends them deleting and re-pasting things that were fine, which is the more expensive error of the two.
145. **The recipient arithmetic for an intro is a pure function, because its edge cases are where the embarrassment lives.** `Ctrl+Shift+I` drops the introducer to Bcc and promotes the introduced party to To — the one gesture where getting Bcc wrong is publicly humiliating. The rules that are easy to miss are all encoded in `lib/intro-forward.ts` and tested: the introducer who also Cc'd themselves must not be left in To *while* being Bcc'd; your own address never survives; a Cc containing only you falls back to the To line rather than opening a blank reply; duplicates collapse case-insensitively while preserving the sender's ordering, because that ordering often encodes who the introduction is for. The greeting degrades to a literal `[Name]` placeholder rather than addressing someone as their email address.
146. **A moving highlight has to drag the viewport with it.** Both the command palette and PickerShell advanced their selection on Arrow/Ctrl+J without ever scrolling, so holding Down walked the selection out of a `max-h` list and left the user steering something off-screen. One shared hook (`block: "nearest"`, so visible rows don't jitter), applied to both — the bug existed twice because the two lists were written separately.
147. **The day panel shows the day.** It had grown a navigable mini-month and a per-calendar checkbox list above the agenda, pushing the answer it exists to give below the fold. Both are gone; events keep their per-calendar colour so the grouping stays legible, and visibility toggles remain in Settings → Mail, which is where they were already exposed (`CalendarWeek` only ever *read* `hiddenCalendars` and never offered a control). The rail's two destinations became one pill with a sliding thumb and line-drawn SVGs — the design file's own note explains why: the grid glyph "doesn't read as a calendar".
148. **Attribution credited an app that no longer exists.** Unsplash's terms require every photo and photographer link to carry the app's `utm_source`; ours still said `fission_mail` two rebrands later. Its only visible surface is a query string on a photographer's profile, so nothing would ever have surfaced it — pinned now by a test that rejects the retired brands by name, because the failure mode is silence rather than breakage.
